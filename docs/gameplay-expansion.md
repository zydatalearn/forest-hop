### 0.1 已实现的玩法

| 系统 | 现状（来自代码） |
| --- | --- |
| 画布/相机 | 逻辑尺寸 360×576；世界坐标固定，`camera` 只跟随"新高" |
| 物理 | 重力 `gravity = 1440`，普通起跳 `jumpSpeed = -480`，弹簧 `springSpeed = -900`；固定 1/120 s 步进 |
| 水平控制 | 240 px/s；键 `ArrowLeft/Right`、`A/D`；触屏按住屏幕左/右半区；左右边缘可穿越（`wrap`） |
| 得分 | `score() = Math.max(0, Math.floor((458 - highest)/10)) + bonusScore` |
| 平台 | 60×18；普通 / `fragile`（踩一次断裂）/ `spring`（黄色弹簧）/ `motion`（横向移动）|
| 危险物 | `hazard = {kind:"bomb", radius:15}`，只放在 `extras` 备选板上，碰到即 `finish()` |
| 拾取物 | `item`：松果 +10、钻石 +30，`radius 10`，每件只计一次（`collected`） |
| 难度曲线 | `routeScore = (526 - previous.y)/10`，`difficulty = min(1, routeScore/300)`；间距 50→68；`routeScore≥120` 出现必踩弹簧大跨度；`routeScore≥180` 备选板出炸弹；`score()≥2000` 板开始横向移动，速度 12→36 px/s |
| 安全路线 | 主路线无炸弹且可达；备选板 0–1 块；必踩弹簧及其下一块板不会断裂 |
| 元系统 | 昵称锁定、本机前 3、联机前 10（CloudBase/Worker 二选一）、上传确认 |

### 0.2 与"新增玩法"直接相关的约束（设计必须遵守）

1. **主路线永远可达、无炸弹**：任何新元素都不得放置在必须经过的路径上造成"必死"。
2. **备选板复用现有判定**：`tests/platform-route.cjs` 断言 `extras.length ≤ 1`、`extra.y === target.y`、炸弹仅出现在 `extras` 的备选板上。
3. **拾取物必须"立在自己所属木板正上方"**：现有断言 `item.x === platform.x + 30 && item.y === platform.y - (spring ? 38 : 18)`。
4. **不得让新道具与上层木板重叠**：`nextPlatform` 里已有"道具与上方板重叠则删除"的检查。
5. **单帧耗时敏感**：`step()` 以 1/120 s 跑，新增逻辑要 O(平台数)，禁止在 `step` 内做分配密集或 DOM 操作。
6. **移动端优先**：触屏只有"左右半区按住"这一输入，新道具的触发方式必须能被触屏自然表达。
7. **素材约定**：图片走 `assets/images/runtime/*.webp`，透明通道，进入游戏前统一 `decode()`。

## 1. 设计目标与原则

**目标**：在"往上跳"这一核心循环不改变的前提下，增加**决策维度**与**容错空间**，让中后期（1000 分以后）不再只是"间距更大"的线性加难，而出现"用不用、什么时候用"的策略选择。

**原则**

- **P1 不破坏既有手感**：默认状态（未拾取任何东西）与原版 1.0.4 完全一致。
- **P2 安全主线不变**：道具是"加爽点/给容错"，不是"必选项"；不拿道具也能通关既定路线。
- **P3 一屏可懂**：任何新道具都用一个图形 + 一个短名 + 一句话说明，HUD 不遮挡木板与角色（沿用 README 的布局约定）。
- **P4 可测试**：所有生成规则可用 `tests/platform-route.cjs` 的确定性随机复现（`Math.random` 被注入种子）。
- **P5 可关闭**：每类玩法用一个开关（如 `FEATURES.dash`）灰度，便于回滚，避免"一改全崩"。

## 2. 道具系统总体架构

现有 `item` 是**拾取即结算**（碰到即加分）。冲刺这类需要"主动择时使用"的玩法不能用同一模型，因此引入两条并行轨道：

### 2.1 两类道具

| 类型 | 语义 | 触发 | 例子（现有/新增） |
| --- | --- | --- | --- |
| **拾取型 Pickup** | 碰到立刻生效，一次性 | 无需操作 | 现有：松果、钻石；新增：护心果、磁石松果、慢时松果 |
| **携带型 / 主动 Charge** | 碰到后进入"充能槽"，玩家按键触发 | 键盘 `↑`/`Space`/`K`；触屏"冲刺"按钮 | 新增：冲刺、弹簧靴、羽毛（二段跳） |

两类共用一套"生成位置"逻辑（现有 `platform.item`），通过 `item.kind` 区分；携带型多一层"槽位状态"。

### 2.2 状态机（携带型）

```
未持有 ──拾取──▶ 待用(charges=1..2) ──触发──▶ 生效中(effectUntil) ──超时/结束──▶ 待用 或 未持有
```

- `charges`：可堆叠上限 2；同种再拾取则 +1，满则只加少量分（避免浪费感）。
- `effectUntil`：用 `performance.now()` 计时（与现有 `compressedUntil` 用法一致）。
- 死亡 / 重开：清空槽位（在 `restart()` 里重置，和 `bonusScore/fragments/pickupEffects` 一起）。

### 2.3 生成规则（关键：保持安全主线）

沿用 `nextPlatform(previous)` 里已有的 `platform.item` 生成点（`Math.random() < 0.26`），仅扩展 `kind` 的取值分布：

```
if (Math.random() < 0.26) {
    // 权重抽签：普通道具为主，功能道具随难度小幅提升出现率
    const roll = Math.random();
    let kind;
    if (roll < 0.62)      kind = Math.random() < 0.25 ? "diamond" : "pinecone"; // 分值类（保持现状比例）
    else if (roll < 0.80) kind = "shield";       // 护心果
    else if (roll < 0.90) kind = "dash";         // 冲刺
    else if (roll < 0.96) kind = "magnet";       // 磁石松果
    else                  kind = "glide";        // 滑翔叶
}
```

并在难度门槛上做保护（早期不出现、风险段不出现）：

- `routeScore < 60`：只出分值类（松果/钻石），新手期不引入新信息。
- `kind === "dash"` 仅当 `routeScore >= 60`；`shield` 仅当 `routeScore >= 40`。
- **必踩弹簧段（`requiredSpring`）与其上一板不出携带型道具**，避免"必须先跳再操作"的手忙脚乱。

> 兼容性：`item` 仍严格满足 `x = platform.x + 30`、`y = platform.y - (spring ? 38 : 18)`，并继续接受"与上方木板重叠则删除"的裁剪，测试断言不受影响。

### 2.4 与炸弹的区别

**新道具一律不进入 `hazard` 字段**，`hazard` 仍只用于炸弹。这样 `tests/platform-route.cjs` 中"炸弹必须在备选板上、kind 必须是 bomb"的断言保持成立。

## 4. 冲刺 Dash（重点）

### 4.1 一句话定义

> **拾取"疾风冲刺"后获得一次充能；按下触发键，角色朝当前朝向以约 780 px/s 水平冲出约 0.3 s，期间可"撞碎"炸弹并得分。**

### 4.2 为什么这样设计

- **不破坏核心循环**：冲的是**水平**方向，y 方向弧线基本不变，仍是"跳-落-踩板"，只是给了横向容错与"反杀炸弹"的爽点。
- **有决策**：充能上限 2、跨越大间距或撞炸弹二选一，玩家要判断"现在用还是留给下一段"。
- **能救场**：横向距离算错、板在移动、炸弹挡路时，冲刺是最有用的解。
- **触屏可实现**：一个固定按钮，或"从屏幕下沿上滑"，均不与现有"左右半区按住"冲突。

### 4.3 参数（建议默认值）

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| `dashSpeed` | `780` px/s | 约为普通横移（240）的 3.25 倍 |
| `dashDuration` | `0.30` s | 满冲约 234 px，可跨越大半个屏宽 |
| `dashChargesMax` | `2` | 堆叠上限 |
| `dashCooldown` | `0.5` s | 防止连按无缝位移（也可设 0，由充能限制） |
| `dashBombScore` | `+15` | 撞碎炸弹得分 |
| `dashBombMax` | `1` / 次冲刺 | 一次冲刺最多撞碎 1 个炸弹 |
| `dashFacingLock` | `true` | 冲刺期间朝向锁定在触发瞬间 |

### 4.4 触发方式

| 平台 | 操作 |
| --- | --- |
| 键盘 | `ArrowUp` / `Space`（仅在游戏中，非结束态）/ `KeyK` |
| 触屏 | 右侧固定"冲刺"按钮（圆形，位于 `#right` 上方空档）；或从屏幕**下沿向上滑**（`pointerdown` 在下 15% 区域且 `pointerup` 明显上移） |

> 冲突处理：现有 `keydown` 里 `Space` 只在 `gameOver` 时重开。冲刺需要"游戏中 Space 生效"，实现时把分支写成"若 `gameOver` → `restart()`；否则若持有冲刺 → 触发冲刺"，并保持 `preventDefault()`。
> 触屏按钮需加入 `pointerdown` 的忽略选择器（现在是 `.hud, #ranking, dialog`），追加 `.item-button`。

### 4.5 与现有系统的交互（逐条）

| 交互对象 | 行为 |
| --- | --- |
| **横向移动** | 冲刺期间覆盖 `player.x += direction * 240 * dt`，改为 `+= dashDir * dashSpeed * dt`；普通左右键在冲刺期间忽略（或叠加很小，见变体） |
| **左右边缘** | 仍走现有 `wrap`（`x > width → x = -player.width`），可从一侧冲到另一侧 |
| **重力/跳跃** | y 方向不做修改，保持原物理；踩板逻辑不变（仍能落在板上、踩弹簧） |
| **踩弹簧** | 冲刺中踩到弹簧：正常触发 `springSpeed`，同时**结束冲刺**（避免"水平飞 + 垂直弹"叠加成穿模） |
| **踩碎裂板** | 冲刺着地同样触发 `fragile` 断裂（与现有逻辑一致） |
| **炸弹** | 冲刺期间遇到 `hazard`：销毁该 `hazard`（从 `platform.hazard` 删除），`bonusScore += 15`，播放碎片特效（复用 `fragments` 或 `pickupEffects`），**不结束游戏**；每次冲刺最多 1 个 |
| **道具拾取** | 冲刺期间仍可拾取 `item`（默认） |
| **相机/得分** | 不影响 `camera`、`highest`（除非冲刺撞炸弹给分） |
| **移动板速度** | 冲刺穿越移动板时，落板判定照旧；冲刺本身不改变 `movingSpeed()` |

### 4.6 状态与伪代码（仅示意，说明挂载点）

状态字段（建议挂在 `player` 上，随 `restart()` 一起重建）：

```js
player.dashCharges = 0;      // 充能数
player.dashUntil   = 0;      // 冲刺生效截止时间（performance.now() 口径）
player.dashDir     = 0;      // 触发瞬间的朝向
player.dashBombs   = 0;      // 本次冲刺已撞碎炸弹数
player.dashCooldownUntil = 0;
```

`sprint 触发`（放在键盘/触屏事件里，或 `step()` 开头判空）：

```
if (charges > 0 && now >= cooldownUntil && !dashing) {
    charges--; dashUntil = now + 300; dashDir = player.facing; dashBombs = 0;
    cooldownUntil = now + 500;
}
```

`step(dt)` 内、原横移语句处：

```
const dashing = performance.now() < player.dashUntil;
const speed = dashing ? player.dashDir * 780 : direction * 240;
player.x += speed * dt;
```

炸弹判定处（现有 `if (hazard && touchesCircle(hazard)) finish();`）：

```
if (hazard && touchesCircle(hazard)) {
    if (dashing && player.dashBombs < 1) { 销毁炸弹; bonusScore += 15; 特效; player.dashBombs++; }
    else if (player.shield) { 消耗护盾; }
    else finish();
}
```

`draw()`：冲刺期间给角色叠加**速度线/残影**（沿用现成的"左移镜像"绘制分支，不新增图片也能做：半透明重绘 2–3 个拖影），HUD 显示剩余充能与持续时间条。

### 4.7 变体（可择一，供平衡取舍）

- **变体 A（推荐，默认）**：纯水平冲刺 + 撞炸弹。
- **变体 B**：冲刺附带一次性升力（`vy = min(vy, -180)`），可"冲过一小段高度差"，让冲刺也能救"跳矮了"。
- **变体 C**：拾取即触发（不做充能槽），像火箭一样立刻前冲 0.25 s。实现最省，但失去择时决策。
- **变体 D**：冲刺附带穿透（可穿过 1 块木板从下方绕上）。手感强但对可达性影响大，**不建议**。

### 4.8 平衡与边界

- **不产生"跳级"**：冲刺水平位移即使到 234 px，也**不能替代向上跳跃**（y 弧线不变），因此不会跳过整套难度曲线。
- **不给分滚雪球**：冲刺本身 +5，撞炸弹 +15，对分数影响有限。
- **上限 2 充能**：连续两段都能救场，但不至于"全程无敌"。
- **与 2000 分移动板共存**：移动板速度 12–36 px/s，冲刺 780 px/s 仍远高于它，容错成立。
- **与必踩弹簧段共存**：该段本就不生成携带型道具，且冲刺不改变垂直跳跃，保证 `requiredSpring` 断言不受影响。

## 5. 其他道具详细设计

### 5.1 护心果 Shield（拾取型，携带 1 层）

- **效果**：抵挡一次致死 —— 炸弹撞击或跌落（`player.y - camera > height`）。
- **表现**：角色外圈一层琥珀色光环；受击时碎裂。
- **掉落死亡处理**：`finish()` 处若持有护盾则改为"消耗护盾 + 把玩家拉回最后安全高度上方一点"，避免"明明有盾却掉下去"的挫败。
- **注意**：护盾不改变主路线安全性，只是容错。

### 5.2 弹簧靴 Spring Boots（携带型）

- **效果**：下一次踩板以 `-900`（等同弹簧）起跳，持续到用完或落地即消耗。
- **用途**：越过"危险 + 大间距"的组合段，或抢占上方高价值道具。
- **交互**：与现有弹簧叠加时取更强（`springSpeed`）。

### 5.3 滑翔叶 Glide（携带型，持续 2.5 s）

- **效果**：生效期间，下落速度 `vy` 上限被夹到 `+220`（原可到 +500 以上），横移强化到 300 px/s。
- **触发**：拾取后自动生效 2.5 s，或"按住不放才生效、松开停止"（更像滑翔，操作要求更高）。
- **用途**：横移不过去时保命；穿过窄缝。
- **视觉**：角色上方画一片叶子，`vy` 被夹时画下坠气流线。

### 5.4 磁石松果 Magnet（拾取型，6 s）

- **效果**：半径 90 px 内的 `item` 向玩家靠拢（每帧做一次简单线性插值），仍"每件只计一次"。
- **实现注意**：只移动 `item.x/item.y`，不改它所属木板，避免破坏"道具必须在自己板上方"的生成断言 —— **生成期**断言不受影响，**运行期**吸附是允许的（断言只检查生成结果）。

### 5.5 羽毛 Feather（携带型，二段跳）

- **效果**：空中可再跳一次（`vy = jumpSpeed`），落地前的 0.35 s 内可触发。
- **用途**：补一次容错，或"跳起吃道具再跳回来"。
- **防滥用**：每次落地重置，不可连续叠加。

## 7. 连击与收集链（不依赖新美术，纯逻辑）

- **连击 Combo**：在不落地断裂的情况下连续踩不同木板，每 5 板 ×1.1 倍道具分（上限 ×2）。HUD 显示"×1.5"小字。
- **收集链**：同一屏内收齐"松果+钻石"给 +20 额外分，鼓励横向取舍。
- **风险回报**：撞碎炸弹 +15（与冲刺联动）；离屏边缘吃道具额外 +5，鼓励贴边操作。

以上三项都只改 `bonusScore` 的加法路径，是"低风险、高体验"的增量。

## 8. HUD / 交互变更（移动端优先）

- **道具槽**：HUD 右侧或画布右上角，两个小圆框显示当前充能（图标 + 数字），下方细条显示持续时间。**位置必须避开木板区**，沿用 README"昵称/排行/分数位于画布上方独立栏"的约定。
- **冲刺按钮**：圆形，位于右侧控制键上方空档，直径 ≈ 控制键的 0.8 倍；按下高亮（复用 `.pressed` 样式）。
- **触屏手势**：从屏幕下沿向上滑 = 触发冲刺（与"左右半区按住"不冲突，因为起点在下 15% 且要求明显上移）。
- **提示文案**：底部那行 `松果 +10 · 钻石 +30 · 避开木板上的炸弹` 扩展为含冲刺/护盾的一句话说明。

## 附：与原版数值的一致性声明

本方案**只增加"板上放什么"**（`item.kind` 与运行期状态），**不改动**以下既有公式与常量：
`gravity = 1440`、`jumpSpeed = -480`、`springSpeed = -900`、`gap = 50 + difficulty*18`、
`springGap = 150 + difficulty*60`、`movingSpeed() = 12 → 36`、`difficulty = min(1, routeScore/300)`、
`maxShift` 约束、`score()` 公式、`camera` 逻辑。

因此原版"默认手感"与"主路线可达性"保持不变，新增玩法是**可关闭、可灰度**的增益层。


## 当前实现补充：高度分段

最高爬升距离以 10 个世界像素折算 1 m；原地跳不增加高度。难度不再由道具积分或等待时间推进。

| 最高高度 | 变化 | 新增高度分及零食奖励倍率 |
| --- | --- | --- |
| 0–1999 m | 普通炸弹概率随高度逐渐增加，1000 m 达到上限 | 1 倍 |
| 2000–4999 m | 移动板；每 5 秒生成炸弹排，出现后 1.2 秒碰撞宽限，保留连续安全空位 | 1.25 倍 |
| 5000–7999 m | 全部木板踩后碎裂 | 1.5 倍 |
| 8000 m 起 | 饱食度最多 15 秒，松果补 4 秒、钻石补 8 秒，耗尽结束 | 1.75 倍 |

高度积分按爬升区间分别结算，不会在跨段时追溯放大旧分数。零食倍率与既有连跳倍率相乘。炸弹排替换普通危险物；空位覆盖当前主路线及移动范围，弹簧越过多块板时也保留通道。饱食阶段主路线每三块板安排零食，若遮挡则移到后续板。暂停冻结碰撞宽限、波次及饱食倒计时。炸弹按世界位置静止绘制，无闪烁、边框或提示文字。

验证：`tests/difficulty-pressure.cjs` 检查阶段边界、道具积分隔离、饱食补充、暂停和重开，并分别在 2000/5000/8000 m 连续模拟 60 秒主路线跳跃。`tests/platform-route.cjs` 检查生成与单跳可达性，独立关闭波次和饱食，避免把单跳模拟当作连续玩法验证。
